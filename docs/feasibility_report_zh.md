## 0. 一句话结论

**推荐只做 LLM 岗方向，项目是："Hint, Don't Solve"——游戏内伴侣的玩法落地后训练，以及"在模拟玩家上训练出的收益，换一批没见过的玩家还剩多少"的研究。**
它命中 LLM 岗 JD 的全部必备项（后训练 / 交互日志中的隐式信号 / 训练基建）和两个加分项（Roleplay / 实时性），并直接对标他们 2026 年最新论文的研究问法。所有关键环节已在 n05 上实测跑通。

**约束（2026-11-08 确认）：零人力——没有试玩玩家、没有人工标注。** 所有评测必须自动化，"真人"只能通过公开的真人数据间接引入（§4.4）。

## 2. 从他们的代码与论文读出的"研究品味"

animeGRPO 的 README/RESULTS 是最好的面试官画像：
1. **奖励被 hack 是主线**：只优化主观分会让 34% 输出崩坏；加权求和只减半；**区间硬门控（zone gate）**才把违规压到 6%。
2. **约束感知的 checkpoint 选择**：原始分数一直涨到 1710 步，但约束奖励在 1400 步见顶。
3. **诚实的负结果**（VAD arousal 失败、AS-only checkpoint 丢失都写明）。
4. **一定要做真人盲测**，并问"预测器奖励何时与人类感知一致"。
5. 工程细节写清楚（哪些超参是"承重"的、为什么）。

→ 我们的项目应当在**结构上复刻这套问法**，但换到他们 LLM 伴侣的问题域。

## 4. 推荐项目：Hint, Don't Solve

### 4.1 一句话
在信息不对称的中文合作解谜世界里，后训练一个**保持人设**的伴侣 LLM：它要帮玩家解开谜题、但不能替玩家算出答案，不能编造游戏状态，回复要短到能实时对话；然后检验"在模拟玩家上训练得到的收益，换成没见过的玩家（含用真实中文用户日志训练的真人化模拟器）还剩多少"。

### 4.2 为什么这能打动他们
- **JD 逐条命中**：LLM 后训练（SFT + 多轮 GRPO）；人类反馈（真实中文用户日志训练的真人化模拟器 + 交互日志中的隐式信号：放弃、求提示、通关轮数、对话长度）；训练基建（确定性可续跑的 episode 采样器、跨节点 rollout/评判服务、约束感知 checkpoint 选择）；Roleplay 加分；延迟加分（简洁性预算 + 实测首句延迟）。
- **直击"not just a RP chatbot"**：伴侣的价值由**可验证的游戏状态**来衡量，而不是聊天评分。
- **研究问法与他们最新论文同构**："When do simulator-trained companion gains survive a shift in players?" ↔ animeGRPO 的 "When does predictor-based RL align with human perception?"。
- 中文、原创角色、游戏内实时互动——和 I_NORI 的实际产品形态一致。

### 4.3 新颖性定位（已检索核实）
没有找到同时具备以下要素的工作：伴侣作为**帮助者而非解题者**、奖励来自**归属于玩家的可验证游戏进展**、**不剧透约束**、**人设**、**实时简洁预算**、并检验**对玩家分布偏移的稳健性**。必须引用并区分的最近邻：
1. **PedagogicalRL**（2505.15607, EMNLP'25）：AI 导师-模拟学生，解题率奖励 + 泄露惩罚 λ 的 Pareto 曲线。**机制最近**；区别：游戏状态/行动、信息不对称、人设、编造状态检测、实时性；且他们只用单一学生模型；我们用多家族 + 真人日志训练的模拟器做迁移评测。
2. **CollabLLM**（2502.00640, ICML'25 杰出论文）：多轮感知奖励 + 用户模拟器（MIT 开源）。
3. **Quantifying the Utility of User Simulators**（2605.09808）：**prompt 扮演的模拟用户训练出的助手，在 283 人真人测试中胜率 50.6%（无增益）**；用真实日志训练的模拟器才有 58%。这是我们方案的核心风险；我们用真人日志训练的模拟器和交叉模拟器评测来正面处理它。
4. 人设 RL：CRPO（2605.25511，有代码）、HER（2601.21459）、RAPO（2606.27025）；游戏队友：PUBG Ally（2609.29837，蒸馏无 RL，编造状态是头号失败）；VR 伴侣用户研究（2609.13727，"代玩"模式 0 人偏好）。

### 4.4 研究设计
**环境**（已有原型 `companion/proto/env.py`）：中文、程序化生成、信息不对称——伴侣知道规则看不到机关，玩家看得到机关并且是唯一能操作的人。计划 6 类谜题，并加入"跨世界记忆"（第 1 个世界学到的事实在第 3 个世界才用得上），对应 I_NORI 的"remembers across worlds"。

**可验证指标**：玩家通关、剧透（伴侣先于玩家给出完整答案，规则判定 + 评判模型复核）、**编造状态**（伴侣断言的映射/状态与她的已知信息矛盾、凭空给出具体密码、替玩家操作——规则可判；无数字的编造规则交给"只看她已知信息"的评判模型，并用规则子集校验它）、玩家放弃、回复长度/首句延迟。人设由评判模型打分，并用人工标注的小集合校准。

**奖励消融（对标 animeGRPO 的 Table 1）**：
- A 仅进展 → 预期学会剧透（hack）
- B 加权求和
- C **区间门控**：剧透/编造状态 → 硬惩罚；可行区内再优化进展、人设、简洁
- D C + 多轮感知（CollabLLM 式前瞻 rollout）

**零人力评测体系（三层）**：
1. **可验证层（核心，规则判定）**：玩家通关、剧透、编造状态、放弃、通关轮数、回复长度。全部由游戏状态和规则算出，不依赖任何评判模型。
2. **评判层（人设）**：两路独立评判并报告一致性——① 我们的中文评分细则 + Qwen3.5-122B；② **CharacterJudge**（thu-coai，在 CharacterBench 人工打分上微调的 7B 中文评判模型，公开免申请），相当于借用别人的人工标注做间接校准。两者分歧大的地方单独分析（RAPO/CoSER 都报告过评判模型被 hack）。
3. **玩家分布迁移层（代替真人试玩）**：
   - 训练用"玩家池 A"：Qwen3.5-122B 扮演 4 种玩家类型。
   - 留出评测用：① 不同模型家族的模拟器；② 训练中没见过的玩家类型；③ **真人化模拟器**——用 WildChat 中 7.3 万段真实中文多轮对话（34.6 万条用户发言，追问中位 20 字、38% ≤15 字）按 2605.09808 的配方训练，学的是真人的简短、含糊、不耐烦和中途离开。
   - 产出 **交叉模拟器迁移矩阵**（训练于 X、评测于 Y），这正是 animeGRPO 的 cross-axis 迁移表的同构物。2605.09808 证明交叉模拟器评测是"对真人泛化"的可行代理，而真实日志训练的模拟器比 prompt 扮演的更接近真人。
   - **局限性如实写明**：没有真人试玩，结论是"对玩家分布偏移的稳健性"，不是"真人玩家体验提升"。
- 进阶（时间允许）：用真人化模拟器的对话日志挖掘隐式信号（放弃、重问、求提示、回复变短），训练 Chai 式参与度奖励模型，与可验证奖励对比——对应 JD 的"从人机交互日志挖掘隐式信号"。

### 4.5 算力规划
- n05：策略训练（4B 主实验，9B 做规模验证），8 卡
- n06：玩家模拟器与评判服务（Qwen3.5-122B-A10B-FP8，TP4 ×2 副本）
- n04（空出后）：并行奖励消融 / 评测
- 实测：32 局 × 约 5 轮的 rollout ≈ 30 s/步（9B 模拟器）；换成 122B 模拟器预计 1–2 min/步，单个消融臂 300–500 步 ≈ 半天到一天

## 5. 已完成的上卡验证（n05）

| 编号 | 内容 | 结果 |
|---|---|---|
| E1 | 原型环境 64 局基线（Qwen3.5-9B 同时扮演伴侣和玩家） | 通关 57.8%、**剧透 21.9%**、放弃 15.6%、伴侣平均 148 字（远超"一到三句"）。读原始对话发现：**剧透检测准确**；伴侣会**编造看不到的锁面符号**并把玩家带到放弃——可规则验证的新奖励信号；**人设语气基座已经不错**，短板是"在角色里把游戏玩好"。9B 当玩家模拟器质量差（JSON 混乱、乱码、也编造）→ 必须用更强模拟器 |
| E4 | ms-swift 4.6 多轮 GRPO + 自定义 gym 环境 + 外部玩家模拟器，Qwen3.5-4B 全参 3 步 | **端到端跑通**；奖励均值 −0.63、组内标准差 0.55、零方差组 0；修复了一个事件循环 bug |
| E5 | 单用户实时延迟（9B，H20，vLLM） | TTFT p50 64 ms，首句 p50 148 ms，整句 p50 280 ms → 服务器端延迟不是瓶颈，**回复长度**才是 |
| E6 | WildChat 中文 RP 隐式信号量（已扫 48/86 分片，178 万对话） | 中文 RP 约 3.6k，≥3 轮约 1k，OOC/否定/正向追问仅几十条且多为噪声 → 公开日志不够，隐式信号必须来自自己的试玩 |
| E2 | 换强模拟器：伴侣 9B，玩家 Qwen3.5-35B-A3B-FP8，64 局 | 通关 64.1%、剧透 21.9%、放弃 9.4%，64 局 48 s。35B 玩家推理更连贯（能复述符号、会质疑伴侣），但**平均每句 96 字，而 WildChat 真实中文追问中位 20 字** → "真人感"差距可量化，佐证需要真人化模拟器。122B 仍在下载 |
| E2b | **编造状态检测**（`proto/fabrication.py`，规则：映射说错 / 伴侣凭空给出玩家没说过的具体密码） | 编造出现在 22–34% 的密码锁局次；**有编造的局次通关 14–18%，干净局次 76–90%；放弃 29–36% 对 0–12%**。抽查：多数为真编造（"倒着读……那是 3871"，伴侣自己输入【TRY 1298】），也有误报（假设性计算、"四边形"），估计精度 75–85%；凭空编造的规则（不含数字）规则抓不到 → 设计为"规则门控 + 只看伴侣已知信息的评判模型"，用规则子集交叉校验评判模型 |
| E7 | 真人化模拟器的数据量（WildChat-4.8M 全量） | 中文对话 26.6 万，多轮 7.3 万，用户发言 34.6 万；追问中位 20 字，38% ≤15 字 → 足够按 2605.09808 配方训练 |
| E8 | 零人力人设校准 | CharacterBench 公开测试集不含对回复的人工打分；但其评判模型 CharacterJudge（人工打分训练）公开可用 |
